# Backlog

Backlog разделяет продуктовые гипотезы и исполнимые задачи:

- `hypotheses.yaml` — предположения о пользовательской ценности, способы проверки, свидетельства и решения;
- `tasks.yaml` — источник правды для UI-, UX-, продуктовых и архитектурных задач реализации.

Гипотеза описывает, почему изменение может быть полезно. Задача описывает работу,
которую нужно выполнить. Одна гипотеза может породить несколько задач, но не считается
подтверждённой только потому, что реализация завершена.

Жизненный цикл гипотезы: `proposed` → `ready-for-test` → `testing`, затем
`validated`, `invalidated` или `inconclusive`. Для отложенных гипотез используется `parked`.

Минимальный процесс:

1. Новая задача получает стабильный ID и статус `backlog`.
2. После уточнения критериев готовности задача переходит в `ready`.
3. Перед началом работы статус меняется на `in-progress`.
4. `done` ставится только после выполнения всех `acceptance` и проверки результата.
5. Если работа остановлена внешней причиной, используется `blocked`, а причина добавляется в задачу полем `blockedBy`.

Задачу можно передать агенту по ID: «возьми UI-003». Агент сначала читает актуальную запись, меняет только связанные файлы и отмечает результат в том же источнике.
