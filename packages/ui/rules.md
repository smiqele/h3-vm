# UI: дизайн-система и правила

UI-слой отвечает за визуальный язык и строительные блоки, но не определяет
бизнес-сценарии конкретного сервиса.

## Границы слоя

UI хранит:

- примитивы и компоненты;
- семантические переменные;
- темы и режимы контрастности;
- визуальные и accessibility-контракты;
- допустимые свойства и состояния компонентов.

UI не хранит:

- жизненный цикл виртуальной машины;
- последовательность пользовательского сценария;
- тексты конкретной ошибки API;
- состав конкретного экрана.

## Правила

1. Компоненты используют компонентные токены, а компонентные токены ссылаются
   на semantic и core там, где это сохраняет понятный контракт.
2. Состояние нельзя передавать одним цветом.
3. Каждое интерактивное состояние должно быть доступно с клавиатуры.
4. Публичное свойство компонента описывается в `components.yaml`.
5. Экран может использовать только зарегистрированные компоненты.

## Читаемость кода

Код компонента должен объяснять его устройство человеку без предварительного
разбора реализации.

1. Структура компонента отражается в разметке и стилях: база, слои, варианты,
   состояния и размеры разделены явно.
2. Название описывает ответственность сущности: `surface`, `content`, `icon`,
   `label`, а не технические сокращения без контекста.
3. Вычисляемые условия получают имена (`isDisabled`, `label`) до разметки.
4. JSX-свойства и CSS-правила не уплотняются в длинные однострочные выражения.
5. Комментарий объясняет архитектурное решение или порядок слоёв, но не
   пересказывает очевидный код.
6. Локальная визуальная формула остаётся рядом с компонентом. Общая абстракция
   появляется только после реального повторения в нескольких компонентах.
7. Инструменты демонстрации состояния не входят в production API компонента.
   Для принудительных hover и active Design Lab использует отдельный preview.
