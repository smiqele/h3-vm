# Обновление компонента

## Анализ влияния

Перед изменением сопоставить запрос с публичными props, variants, states, behavior, tokens, потребителями и продуктовыми прототипами. Существующие изменения пользователя в рабочем дереве сохраняются.

## Порядок работы

1. Обновить реализацию и минимально необходимый публичный API.
2. При изменении визуального контракта обновить component tokens.
3. Синхронизировать `components.yaml`.
4. Обновить controls Preview и генерируемый из их состояния пример Code.
5. Обновить Design при изменении назначения, варианта, состояния, геометрии или поведения.
6. Проверить все известные места использования и продуктовый прототип.
7. Выполнить автоматические и визуальные проверки.

Не следует расширять API ради единственного внутреннего случая, если задачу решает композиция через существующие публичные свойства.
