# Создание компонента

## Перед началом

Проверить, что задача действительно требует нового компонента, а не варианта, композиции или UX-паттерна. Найти ближайшие компоненты и существующие semantic roles.

## Порядок работы

1. Определить пользовательскую задачу, границы и нативную семантику.
2. Создать публичный TypeScript API и реализацию в `packages/ui`.
3. Добавить только необходимые component tokens и использовать semantic colors.
4. Экспортировать компонент через публичный API пакета.
5. Добавить запись, варианты, состояния и правила в `components.yaml`.
6. Зарегистрировать маршрут в manifest и каталоге Design Lab.
7. Собрать Preview, Design и Code через общий `ComponentDocumentation`.
8. Проверить компонент внутри подходящего продуктового контекста.
9. Выполнить обязательные проверки и визуальный аудит.

## Нельзя

- Добавлять CSS-props вместо смыслового API.
- Создавать локальную палитру или дублировать semantic tokens.
- Показывать галерею вариантов в Preview.
- Делать отдельный shell документации.
- Добавлять компонент без keyboard, focus и доступного имени.
