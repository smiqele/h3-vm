# Работа с токенами

Перед изменением токенов прочитать человекочитаемую [архитектуру токенов](/docs/ui/token-analysis).

## Правила

- Core хранит сырые шкалы и не задаёт смысл интерфейса.
- Semantic tokens задают роль поверхности, текста, границы, состояния или feedback.
- Component tokens фиксируют устойчивую геометрию и визуальный контракт конкретного компонента.
- Компонент не выбирает UI-цвет напрямую из core, кроме документированного внутреннего оптического эффекта.
- Новый token добавляется для повторяемого контракта, а не для каждого CSS-свойства.
- Theme-dependent token имеет light и dark значения и проверяется на контраст.
- Preview получает тему через полный локальный scope, генерируемый тем же token generator.

## Порядок изменения

1. Найти существующую semantic role.
2. Определить минимальный слой изменения: core, semantic или component.
3. Изменить JSON source в `packages/ui/tokens/`.
4. Использовать token в компоненте без копирования значения.
5. Выполнить `npm run tokens:generate`.
6. Проверить обе темы в Design Lab и прототипе.
7. Запустить полную проверку контраста и спецификаций.
