# Работа агента с дизайн-системой

Этот раздел содержит операционные контракты для создания, обновления и проверки компонентов. Документы рассчитаны на агента, но остаются читаемыми для дизайнера и разработчика.

## Когда читать

- Перед изменением страницы компонента — [Стандарт страницы компонента](/docs/agents/component-documentation).
- При создании нового компонента — [Создание компонента](/docs/agents/create-component).
- При изменении существующего — [Обновление компонента](/docs/agents/update-component).
- При проверке качества — [Аудит компонента](/docs/agents/audit-component).
- При изменении переменных — [Работа с токенами](/docs/agents/tokens).
- Перед завершением работы — [Проверки и готовность](/docs/agents/checks).

## Общий принцип

Агент не создаёт параллельный источник истины. Он сопоставляет TypeScript API, YAML-спецификацию, tokens, документацию и прототип, изменяет только затронутые уровни и проверяет их согласованность.

Если требования конфликтуют или требуют продуктового решения вне текущей задачи, агент фиксирует противоречие и запрашивает направление, а не угадывает новый контракт.
