# States and feedback

## Состояние ресурса и состояние операции

Состояние ресурса описывает его текущую доступность: например, `running` или `stopped`. Состояние операции описывает действие над ним: `submitting`, `processing`, `succeeded` или `failed`. Эти состояния не должны подменять друг друга.

Источник названий и визуального представления известных ресурсных статусов — `packages/docs/ui/resource-statuses.yaml`. Генератор проверяет записи и создаёт типизированный словарь. Неизвестное значение API получает явное представление `unknown`.

Словарь статусов определяет представление, но не конечный автомат. Допустимые переходы и доступные действия принадлежат ресурсной модели сервиса. Ошибка фоновой операции не заменяет последнее подтверждённое состояние ресурса: пояснение операции показывается отдельно.

## Базовые состояния представления

- `loading` — начальное получение данных;
- `empty` — данные успешно получены, но ресурсов нет;
- `populated` — данные доступны;
- `refreshing` — показаны прежние данные и выполняется обновление;
- `error` — данные получить не удалось;
- `forbidden` — у пользователя нет доступа.

## Обратная связь операции

1. Интерфейс подтверждает, что действие принято.
2. Ресурс получает промежуточное состояние, если операция асинхронная.
3. Пользователь может определить, к какому ресурсу относится операция.
4. Успех отражается в актуальном состоянии ресурса.
5. Ошибка сообщает, изменилось ли состояние ресурса и что можно сделать дальше.

## Уровни обратной связи

- внутри поля — локальная ошибка ввода;
- внутри формы — ошибка отправки или зависимость между полями;
- рядом с ресурсом — состояние конкретной операции;
- на уровне страницы — ошибка загрузки или ограничение всего раздела;
- глобально — событие, не связанное с текущим экраном.
