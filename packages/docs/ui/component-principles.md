# Принципы компонентов

Компонент — переиспользуемый визуальный и технический контракт. Он решает ограниченную интерфейсную задачу, не знает о конкретном облачном ресурсе и получает продуктовый смысл через props и композицию.

UX-паттерн описывает сценарий пользователя, а продуктовая модель — сущности, состояния и операции. Компонент предоставляет строительные блоки для обоих уровней, но не подменяет их.

## Источники истины

- TypeScript-интерфейс определяет публичный API.
- `packages/ui/components.yaml` фиксирует варианты, состояния, правила и связи.
- `packages/ui/tokens/` определяет визуальный контракт.
- Design Lab исполняет компонент и документирует его.
- Прототипы проверяют компонент в реальном продуктовом контексте.

## Формула страницы компонента

```text
Component
├── Preview — один интерактивный экземпляр
├── Design — правила выбора и использования
└── Code — API и синхронизированный пример
```

Preview отвечает на вопрос «что изменится при смене props». Design объясняет назначение, варианты, состояния, геометрию, поведение и доступность. Code показывает актуальное подключение, props, события и ограничения.

## Принципы реализации

- Использовать нативную семантику, когда она соответствует задаче.
- Описывать в API смысл и поведение, а не внутренние CSS-настройки.
- Брать цвета из semantic tokens, устойчивую геометрию — из component tokens.
- Не передавать значение только цветом; сохранять доступное имя, keyboard и focus.
- Проверять компонент отдельно в Design Lab и в составе продуктового прототипа.
- Обновлять документацию вместе с публичным API, состояниями, поведением и токенами.

## Цикл изменения

```text
Решение
→ API и компонент
→ specification и tokens
→ Preview, Design и Code
→ продуктовый прототип
→ автоматические и визуальные проверки
```

Подробные обязательные правила находятся в разделе [Для агентов](/docs/agents/overview). Они написаны так, чтобы дизайнер или разработчик также мог проверить процесс и результат.
