# UI-референсы

Документ сохраняет внешние и ранние внутренние наблюдения, которые могут быть полезны при развитии интерфейса. Референс не является контрактом: решение становится частью системы только после проверки, переноса в UI/UX-спецификацию и реализации.

## MongoDB LeafyGreen

Источник: [mongodb.design](https://www.mongodb.design/).

LeafyGreen рассматривается как пример зрелой дизайн-системы для сложного технического продукта, а не как модель для копирования.

Полезные наблюдения:

- foundations, patterns и components разделены по ответственности;
- страница компонента показывает варианты, состояния, API и рекомендации;
- ошибки, ограничения доступа и пустые состояния рассматриваются как системные сценарии;
- accessibility и правила текста являются частью качества компонента;
- сложные таблицы, формы и навигация документируются в продуктовом контексте.

Что применяем:

- компонент отвечает за визуальный и технический контракт;
- UX-паттерн отвечает за повторяемую пользовательскую задачу;
- Preview, Design и Code проверяют разные стороны компонента;
- системные состояния описываются отдельно от конкретного экрана.

Что не переносим автоматически:

- визуальный язык MongoDB;
- состав компонентов;
- структуру сайта;
- токены, названия props и программные интерфейсы.

Темы для дальнейшего сравнения: DataTable, Sidebar navigation, Empty state, Access restriction, Button и архитектура tokens.

## Ранний референс списка виртуальных машин

При исходном разборе экрана ВМ были выделены:

1. постоянная навигация с Workspace и Project;
2. контекстный путь, заголовок и основные действия;
3. сводка ресурсов и квот;
4. поиск, фильтрация и таблица;
5. контекстная область выбранного ресурса;
6. быстрый доступ к CLI и Logs.

Неподтверждёнными остались назначение правой области, смысл AI-фильтра, источник значений сводки и принадлежность CLI/Logs проекту или выбранному ресурсу.

Часть ранних названий компонентов больше не используется. Актуальные компоненты определяются `packages/ui/components.yaml`, экран — `packages/docs/domains/compute/virtual-machines/screens.yaml`, а продуктовое описание — [документом домена](/docs/domains/compute/virtual-machines).

## Как использовать референс

```text
Наблюдение
→ гипотеза или вопрос
→ проверка на задачах консоли
→ принятое правило в UI/UX-документации
→ спецификация и реализация
```

Непроверенное наблюдение не должно напрямую становиться token, prop, паттерном или обязательным экранным правилом.
